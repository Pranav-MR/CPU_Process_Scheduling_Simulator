SPEAKER 1: WORKING BACKGROUND

Under the Hood: C Data Structures Design

1. struct Process

Stores process state and lifecycle metrics:

  • id[10]: Process identifier
  • at, bt: Arrival & Burst times
  • ct, tat, wt: Computed outputs
  • rem_bt: Remaining burst (RR)
  • completed: Finished flag

2. FIFO Queue DS

Circular/Array Queue for Round Robin:

  • int queue[500] array
  • push() and pop()
  • isQueueEmpty() check
  • Guarantees strict, fair circular ordering in $O(1)$ operations

3. struct Gantt

Tracks exact execution intervals:

  • id[10]: PID or "IDLE"
  • start, end: Timeline bounds
  • Merges consecutive runs and handles gaps where CPU is waiting for arrivals

SPEAKER 2: ALGORITHM LOGIC

Algorithm 1: First Come First Serve (FCFS)

Implementation Logic in C

  • Type: Non-Preemptive
  • Policy: Strict FIFO arrival order
  • Sorts processes ascending by arrival time (at).
  • Advances clock; logs IDLE block if current_time < at.
  • Runs job to completion: current_time += bt.
  • Records $CT$, $TAT = CT - AT$, and $WT = TAT - BT$.

Analysis: The Convoy Effect

Advantage: Simplest scheduling logic, zero context switching overhead.

Major Drawback: If a CPU-heavy process arrives first (e.g., Burst = 20), all subsequent short jobs (e.g., Burst = 2) must wait in line.

Result: Inflated average waiting time.

SPEAKER 2: ALGORITHM LOGIC

Algorithm 2: Shortest Job First (Non-Preemptive SJF)

Selection Logic in C

  • Type: Non-Preemptive
  • Policy: Select process with smallest Burst Time among arrived jobs.
  • At current_time, scans all uncompleted jobs where at <= current_time.
  • Picks the minimum bt.
  • If ready queue is empty, advances clock to earliest future arrival (CPU IDLE).

Evaluation & Trade-offs

Provable Optimality: SJF yields the absolute minimum average waiting time for any fixed set of processes.

Limitation in Real Operating Systems:

  • The OS cannot predict the exact future burst time of an unknown process before running it.
  • Long processes may starve if short processes keep arriving.
SPEAKER 2: ALGORITHM LOGIC

Algorithm 3: Round Robin (RR) with Queue DS

Preemptive Queue Execution

  • Type: Preemptive, Time-Sharing
  • Time Quantum ($q$): Maximum continuous CPU slice allocated.
  • Pushes arrived processes into FIFO queue[].
  • Pops front process, executes for $\min(q, \text{rem\_bt})$.
  • Enqueues newly arrived processes during this slice.
  • If $\text{rem\_bt} > 0$, re-enqueues back to rear.

Impact of Time Quantum ($q$)

If Quantum is very large ($q \ge \max(BT)$):
Round Robin degenerates into simple FCFS.

If Quantum is very small ($q = 1$ unit):
Frequent context switches cause severe CPU overhead.

Rule of Thumb: About 80% of CPU bursts should be shorter than the time quantum.

SPEAKER 3: METRICS & FORMULAS

Visualization & Performance Evaluation Metrics

Formulas Implemented in Code

  • Turnaround Time (TAT): $TAT = CT - AT$
    Total time process stays in system
  • Waiting Time (WT): $WT = TAT - BT$
    Time spent waiting in ready queue
  • Average TAT: $\overline{TAT} = \frac{\sum TAT}{n}$
  • Average WT: $\overline{WT} = \frac{\sum WT}{n}$
  • CPU Utilization: $\frac{\text{Busy Time}}{\text{Total Time}} \times 100\%$

Gantt Chart Representation

Visual Timeline: Maps process execution slices sequentially along with exact start and end boundary timestamps.

Idle State Tracking: Gaps between process completions and new arrivals are explicitly rendered as IDLE blocks.

Dual Display: ASCII diagram in CLI terminal & responsive colored bars in Web UI.

SPEAKER 3: PERFORMANCE COMPARISON

Comparative Benchmark on Standard Workload

Algorithm Avg Waiting Time Avg Turnaround Evaluation Summary
1. FCFS 5.75 ms 11.25 ms Simple FIFO, suffers from Convoy Effect
2. SJF (Non-Preemptive) 5.25 ms 10.75 ms ✔ OPTIMAL (Lowest Waiting Time)
3. Round Robin (q=2) 9.75 ms 15.25 ms Highest fairness & response, context switch overhead

Why SJF Won on Average WT

By scheduling P2 (Burst 3) immediately after P1, the waiting queue delay for remaining jobs was minimized, confirming theoretical optimality.

Round Robin's Practical Value

Though RR has higher average turnaround, every process gets immediate CPU attention, making it the bedrock of interactive time-sharing systems.

Viva Defense Preparation

Q: Why use a Queue for Round Robin?
A: Ensures fair FIFO cycling: process executes for quantum $q$ and re-enters the rear in $O(1)$ time.

Q: Why isn't SJF used in Windows or Linux?
A: Real OS processes have unpredictable future burst durations.
